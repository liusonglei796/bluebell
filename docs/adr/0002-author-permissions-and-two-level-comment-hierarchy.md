# 明确作者权限分级、二级扁平评论与互动通知规范

## Context
随着多作者协作发帖、二级楼中楼讨论以及消息通知系统的推进，存在三处边界模糊与语义冲突：
1. 帖子支持多作者联合署名（`Authors`），但若任何协作者都能直接软/硬删除帖子，存在误删与权限越界风险。
2. 评论若采用深层递归树结构，在大数据量与移动端分页时性能与交互成本极高。
3. 帖子双向投票（`Vote`）与评论点赞（`Like`）在通知中心被混用，且负向投票通知会恶化社区氛围。

## Decision
1. **作者权限分级（Primary Author vs Co-Author）**：
   - 创建帖子的用户为 `Primary Author`（主作者），唯一享有删除帖子及管理协作者的权限。
   - `Co-Author`（联合作者）享有署名权和协作编辑权，但不可删除整篇帖子，仅可主动解除自身署名。
2. **两级扁平楼中楼结构（Two-Level Threaded Comments）**：
   - 物理与渲染层级强制约束在两级（`Root Comment` 一级根评论 + `Sub Comment` 二级回复）。
   - 楼中楼内所有回复的 `RootID` 必须指向根评论；当回复其他子评论时，通过 `ParentID` 与 `ReplyToUID` 记录上下文并使用 `@某用户` 扁平渲染，避免深层递归树查询。
3. **互动与通知语义归一**：
   - Post 统一使用 `Vote`（+1/-1/0），仅正向投票（`Upvote`）触发通知与未读红点，负向投票（`Downvote`）与取消（`Revoke`）不发送通知。
   - Comment 统一使用 `Like`（单向点赞）。
